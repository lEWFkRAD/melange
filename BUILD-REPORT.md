## What was built

### The service — `service/melange_service.py`

Stdlib-only (`http.server.ThreadingHTTPServer`), binds 127.0.0.1,
default port **8798**. Wraps the canonical bridge over a JSON store
registry (`service/stores.json`, or `$MELANGE_STORES_FILE`). Stores
are opened fresh per request, so every response reflects the disk at
request time; writes are serialized per store.

Preconfigured stores: `desktop-real` (real desktop capture,
screen-only), `workbook`, `workbook-pinned` (carries the M7 house
rules), and `flagship` (generated by the canonical
`flagship.run_flagship` into `service/stores/flagship/` on first open;
that directory is gitignored as runtime data).

**10 routes** (see `service/README.md` for the full table):

- `GET /api/health`, `GET /api/stores`
- `GET /api/store/<id>/branch/<b>` — kind, fidelity, caps, the
  design's refusal sentences for refused ops, steps, **seal =
  `store.verify()` at request time**, fork info with `split_step`,
  house rules with live status, notes.
- `GET .../step/<n>` — per kind: video → frame bytes (content-type
  sniffed; `?meta=1` for JSON), workbook → `{label, values}`,
  session → `{event_kind, screen, payload}`, structure → `{parts}`.
- `GET .../wherefrom/<n>?row&col` — bridge provenance + sentence.
- `POST .../note` — a real `annotation` event via `bridge.add_note`.
- `POST .../fork` — `bridge.try_differently`; with
  `{clamp: {cell, value}}` on workbook branches,
  `house_rules.checked_fork` with pin enforcement.

Fidelity refusals return **403** with the library's own sentence;
house-rule rejections return **422** with the violations and the
rules named; a tampered store returns **200 with `seal: false`**.

### The surface — `service/static/index.html`

The v3 volume adapted to live data: tabs built from `GET /api/stores`
(no baked recordings anywhere in the file), `visualParams` and the
volume legend copied verbatim from player v3, strands parameterized
by the *fetched* fidelity, seal chip reflecting the branch response at
open time, steps fetched on demand (desktop frames are `<img>` URLs
into the step endpoint), transports (play/pause/step/scrub/speed/
space/arrows), notes posted to the service and re-rendered from its
response, the workbook clamp form posting forks (success switches to
the real new branch; a 422 shows the server's named-rule reason
verbatim), where-from on session branches, "Calm the drift" toggle.
If the API is unreachable the page shows exactly that and nothing
else — there is no fallback data to fall back to.

## Deviations and notes, stated plainly

- **Step counts differ from `bridge.versions`.** The bridge counts
  every event in a branch's replay; the service counts *navigable
  steps* per kind (kept pictures / cell frames / events). This is the
  surface's step model, documented in the service docstring and
  README; the split checkpoint is still an event id underneath, and
  `split_step` translates it for the volume.
- **House-rule status needs computable values.** For workbook
  branches the service evaluates the branch (finished-book inputs +
  its own clamp edits, through the workbook profile's Engine) and
  reports real Holding/Broken. For a branch with pins but no
  computable values it reports `Unknown — not computable in this
  service` rather than guessing.
- **openpyxl** was installed into the living-replay venv
  (3.1.5 + et-xmlfile): the canonical workbook profile imports it, and
  both the M7 test and the service's clamp path need it. The service
  itself is stdlib-only; openpyxl is loaded lazily, only when a
  workbook evaluation is requested, via `service/workbook_eval.py`
  (profile located by registry entry / `MELANGE_EXCEL_DIR` /
  `~/workspace/your_files/melange-excel`).
- **The 153-step live-session store is not on this VM** (it lives on
  onyx), so it is not in the registry and the surface does not list
  it. Adding it is a registry entry once the store is copied — the
  session step path (screen + provenance) is already implemented and
  exercised against the flagship branches.
- The workbook profile (`workbook_profile.py`, fixture `.xlsx`) still
  lives with the Excel lane's artifacts in `~/workspace/your_files`,
  referenced by the registry — not vendored into the repo. The
  service treats it as an external evaluator, the same arrangement
  the verified M7 demo used.
- One page bug was caught by the surface test during the build (a
  call to a nonexistent `buildVolume()` in `boot()`), fixed before
  the suite went green.
